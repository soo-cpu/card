# content-pipeline

에이전트 정의: `.claude/agents/` 의 content-planner, script-writer, insta-maker, upload-editor, brand-reviewer.
공통 기준: `references/brand-rules.md` (공개 기준), `references/used-topics.md` (이미 쓴 주제).

## 0. 요청 읽기
- "콘텐츠 N개" → 기본 비율 쇼츠 : 카드뉴스 : 릴스 = 3 : 3 : 2. "4주치" = 쇼츠 12 + 카드뉴스 12 + 릴스 8 (+ 블로그 4).
- 시작 날짜가 없으면 다음 주 월요일부터.
- 실행 폴더 이름: `콘텐츠 {기간} {오늘 날짜} v0` (같은 이름이 있으면 v1, v2 … 덮어쓰지 않는다).

## 1. 준비 (Claude가 직접)
1. 작업 폴더를 만든다 (로컬 스크래치패드 아래 실행 폴더 이름 그대로).
2. 현장 사진 목록: 드라이브에서 '01. 사진'·포트폴리오·랜더링 폴더를 검색해 `현장사진_목록.md` 를 만든다. **읽기만. 원본 이동·복사·삭제·이름 변경 금지.** 공개용 이름(지역+평형)을 같이 적는다.
3. 이미 쓴 주제 갱신: 유튜브 채널 최근 업로드 제목을 RSS(`https://www.youtube.com/feeds/videos.xml?channel_id=UCB1J5nJuUoEYwXYvhJD82ew`)로 읽고, 드라이브 'Claude 자료함'의 '콘텐츠 …', '… 쇼츠 …' 폴더 이름을 확인해 `used-topics.md` 에 빠진 것을 추가한다.

## 2. 기획 — content-planner
- 입력: 요청 개수, 시작 날짜, 실행 폴더 경로
- 출력: `00_편성표.md`. 중복 검사(`scripts/check_content.py dup`)에서 '중복 의심'이 0이 될 때까지 바꾼다.

## 3. 제작 — script-writer 와 insta-maker 를 동시에
- script-writer → `youtube/S01_….md` (쇼츠), `youtube/L01_….md` (롱폼 요청 시)
- insta-maker → `instagram/C01_….md` (카드뉴스), `instagram/R01_….md` (릴스)
- 둘 다 편성표만 보고 일한다. 같은 현장이 겹치는 번호는 서로 첫 문장이 다르게.

## 4. 업로드 문구 — upload-editor
- 각 편 끝에 제목 3안·설명란·고정 댓글, `blog/B01_….md`, `업로드 일정표.md`

## 5. 검토 — brand-reviewer (builder와 다른 에이전트)
- `99_검토 결과.md`. '수정'은 해당 작성 에이전트에게 고칠 문장을 넘겨 고치고 다시 검토(최대 2번).
- '막음' 0건, '수정' 0건이 되면 통과. '보류'는 그대로 두고 `형 결정 필요`에 모은다.

## 6. 정리와 저장
1. 날짜·채널별로 다시 묶는다:
   ```
   콘텐츠 4주치 2026-11-20 v0/
     00_편성표.md
     업로드 일정표.md
     매주 할 일 한 장.md
     99_검토 결과.md
     현장사진_목록.md
     1주차 11-23~11-29/
       youtube/  S01_….md
       instagram/  C01_….md  R01_….md
       blog/  B01_….md
     2주차 …/
   ```
2. `매주 할 일 한 장.md`: 주차마다 촬영할 것 / 검토할 것 / 올릴 것 (대표가 한 장으로 보는 용도).
3. 드라이브 'Claude 자료함' 아래에 같은 구조로 올린다(새 폴더, 기존 파일 덮어쓰기 금지).
4. `used-topics.md` 아래 '회차에서 추가한 주제'에 이번 주제를 추가한다.
5. 작업 현황판 다음 번호에 한 줄 추가하고 요약 숫자를 다시 센다.

## 지키는 것
- 배포·업로드·게시는 하지 않는다. 사람이 올린다.
- 원가·마진·고객 개인정보는 어떤 파일에도 옮기지 않는다 (작업 폴더 포함).
- 문구는 이모지 없이, 사람이 쓴 말투로.
